## 1. Что это и как устроено

```
дев-машина resager-tuf (i7-11370H)          мини-сервер res-i3 (i3-6100U)            ТВ-приставка Xiaomi
─────────────────────────────────           ─────────────────────────────            ────────────────────
исходники фильмов/сериалов           ──SSH──▶  /mnt/media, /home/res/…               браузер или приложение
ffmpeg: собираем MP4 здесь (быстрее)            habits-media-agent :8410  ◀──HTTP──  «Habits TV»
скрипты habits/media-agent/*.py                 nginx :80  /tv/ → :8410                http://192.168.0.79/tv/
сборка агента (Go) и APK                        habits-agent (мониторинг)
                                                        │
                                                        └──WSS──▶ прод telegram.resager.ru (только шина команд
                                                                   пульта с телефона; видео через прод не идёт)
```

- **Медиаагент** (`habits/media-agent`, Go) раздаёт страницу плеера, каталог,
  файлы с Range, постеры, позиции просмотра, APK приложения. Слушает только
  `127.0.0.1:8410`, наружу — через nginx.
- **Страница плеера** открывается на приставке: в браузере (там курсор) или в
  приложении «Habits TV» (там стрелки пульта). Телефон может управлять ею через
  страницу «Пульт ТВ» в Telegram-приложении Habits: приставка показывает код, пульт
  подключается через прод. Эту часть (пульт, прод) для работы с медиасервером
  трогать не нужно.
- **Кодирование** делается на дев-машине: на i3 x264 идёт ~8× реального
  времени, на i7 — 15–24×.

## 2. Доступы и подключение

| Что | Где |
|---|---|
| адрес мини-сервера | `192.168.0.79` (DHCP; имя машины `res-i3`) |
| пользователь | `res` |
| пароль SSH (и sudo — тот же) | `~/.config/habits-recode.conf` на дев-машине (host/user/password, права 0600) |
| ключ подписи APK | `~/.config/habits-tv/release.jks` + `keystore.properties` на дев-машине — **не терять** (см. 8) |

**Как подключаться — только через paramiko** (python3 на дев-машине):

- `sshpass` нет; обычный `ssh` отказывается спрашивать пароль — у хоста сменился
  ключ (в `~/.ssh/known_hosts` старая ECDSA-запись, сервер теперь ED25519;
  known_hosts пользователя не трогали);
- в `paramiko.connect` обязательно `allow_agent=False, look_for_keys=False`, иначе
  аутентификация по паролю падает с «No existing session»;
- sudo: `sudo -S -p "" bash -c '<команда>'` и пароль в stdin;
- команды для удалённой оболочки экранировать `shlex.quote` (не `repr`);
- готовый класс с переподключением: `Remote` в `habits/media-agent/recode-remote.py`:
  ```python
  import importlib.util
  spec = importlib.util.spec_from_file_location('rr', 'habits/media-agent/recode-remote.py')
  rr = importlib.util.module_from_spec(spec); spec.loader.exec_module(rr)
  r = rr.Remote(*rr.load_access())          # доступ из ~/.config/habits-recode.conf
  rc, out, err = r.run('df -h /mnt/media')  # run / pull / push / size / duration / wait_online
  r.close()
  ```
  Передача файлов — через `cat` в канале SSH (`push`/`pull`): SFTP в один поток
  вдвое медленнее (13 против 25–28 МБ/с).

## 3. Мини-сервер res-i3

| | |
|---|---|
| ОС | Ubuntu 24.04, 4 потока i3-6100U, 7,7 ГБ ОЗУ, без Go |
| системный диск | `/dev/sda2` ext4 233 ГБ (свободно ~200) |
| **внешний диск** | `/dev/sdb1` exFAT 477 ГБ, **UUID 7F9F-2FE8 → `/mnt/media`** через `/etc/fstab` (`nofail,uid=1000,gid=1000,umask=022,x-systemd.device-timeout=15s`); свободно ~400 ГБ |
| ffmpeg | 6.1.1 (ставили для проверок; кодировать на нём медленно) |
| nginx | `/etc/nginx/snippets/tv.conf` подключён в `sites-enabled/default`: `location /tv/` → `127.0.0.1:8410`, `proxy_buffering off`, `proxy_max_temp_file_size 0`, `proxy_read_timeout 1h` |
| медиаагент | user-юнит `~/.config/systemd/user/habits-media-agent.service`, бинарник `~/bin/habits-media-agent`, linger включён |
| мониторинг | системный `habits-agent` (`User=nobody`, `ProtectHome=true`) — шлёт метрики на страницу «Servers» |

**Почему диск в `/mnt/media`, а не где его монтирует Ubuntu.** udisks2 монтировал
его в `/media/res/…` только после входа пользователя: медиаагент стартовал
раньше и терял библиотеку сериалов (было 9 сентября), а `/media/res` закрыт ACL
для всех, кроме `res`, — агент мониторинга от `nobody` не видел диск. fstab чинит
оба случая. Перезагрузкой это ещё **не проверено** (см. 10).

Копии до правок: `/etc/fstab.bak-habits`, `~/.config/habits-media-agent.conf.bak-20260917-0846`,
`~/.cache/habits-media/progress.json.bak`.

## 4. Медиаагент

**Конфиг** `~/.config/habits-media-agent.conf` (сейчас):
```ini
roots = /mnt/media/rudb/media/serials/ | Сериалы | video
roots = /home/res/rudb/media/serials/ | Сериалы | video      # пустая — кандидат на удаление
roots = /home/res/rudb/media/music/playlist | Музыка Вероники | music
roots = /home/res/rudb/media/films | Фильмы | video
roots = /home/res/rudb/media/video | Видеоролики | clips  # постеры не ищутся
roots = /home/res/rudb/media/foto | Фото | photo
addr = 127.0.0.1:8410
base = /tv
```
Формат: `путь | Название | вид (video, clips, music, photo)`. Вид `photo` —
раздел «Фото и видео»: в альбомах живут и снимки, и ролики. Ещё
`admin_pin = …` — PIN админки на странице (без него админка выключена),
необязательный `trash_days` (3), `backup_dir` (куда класть копии разметки —
обязательно на ДРУГОЙ диск, иначе копия умрёт вместе с оригиналом; на res-i3
`/mnt/media/rudb/backups/habits-media`), `backup_days` (7) и `low_space_gb`
(10, 0 — не следить). Недоступная папка
(диск не примонтирован) не выбрасывается, а подхватывается, когда появится.

**Кэш** `~/.cache/habits-media/`: `probe.json` (разбор ffprobe), `progress.json`
(«Продолжить просмотр»), `posters/*.miss` (промахи поиска постеров, сутки),
`app/habits-tv.apk`, `photos/` (превью и экранные копии снимков, ~0,3 МБ на
снимок), `room` (постоянное имя комнаты для пульта), `secret` (ключ
подписи ссылок на файлы), `transcoded/` (копии, перекодированные кнопкой на ТВ),
`collections.json` + `collections/<id>.jpg` (папки-подборки и их обложки).

**id файлов и папок — хеш пути** (`sha256(path)[:9]`). Сменили путь — сменились
все id. `progress.json` переживает это: запись хранит `dir` + `rel` без
расширения и находит файл заново (так пережили и `.avi → .mp4`, и переезд диска
— при переезде `dir` переписали скриптом).

**Сборка и выкладка агента** (с дев-машины):
```bash
cd habits/media-agent
GOTOOLCHAIN=auto /usr/local/go/bin/go test ./...
GOOS=linux GOARCH=amd64 GOTOOLCHAIN=auto /usr/local/go/bin/go build -o /tmp/habits-media-agent .
# залить в ~/bin/habits-media-agent.new, chmod +x, mv поверх, systemctl --user restart habits-media-agent
```
Страница плеера `player.html` вшита в бинарник (`go:embed`): правка страницы =
пересборка и выкладка агента.

**Раскладка медиатеки** (визуальный режим, `catalog.go`) — по структуре папок,
не по названиям: сериал — папка с папками-сезонами; фильм — видеофайл или папка
ровно с одним видео; несколько видео без сезонов — мини-сериал; музыка — каждая
папка, где прямо лежат треки; видеоролики — ролик из корня или папка с роликами;
фото — папки первого уровня со снимками (`photos.go`). Пустые «Видеоролики» и
«Фото» не показываются.

**Папки-подборки** (`collections.go`, v2.112) — «Гарри Поттер»,
«Фантастические твари»: карточка в том же разделе, что её содержимое, внутри —
фильмы по порядку. **Виртуальные**: на диске ничего не двигается, запись —
список путей и порядок в `collections.json`. Так фильм может быть и в папке, и
в общем списке (галочка «только в папке» убирает его из общего), а
«Продолжить просмотр», отметки заставки и кадры, привязанные к пути, не
ломаются. Переименование в админке состав переживает (`collStore.move`).
Описание папки — только ручное: в интернете «коллекции» нет.

**Постеры** ищутся при первом показе плитки: IMDb (латиница; различает фильм и
сериал по типу и году — «The Gentlemen» 2019 против сериала 2024) и Википедия
(кириллица, `pilicense=any`). Кладутся **рядом** с фильмом/папкой сериала под
тем же именем (`Fauda.jpg`). Свою картинку можно подложить руками — она главнее.
Название для поиска чистится от релизных тегов (`cleanTitle`, покрыт тестом).

**«Продолжить просмотр»** (`progress.go`): запись на сериал/фильм, до 20, старше
полугода удаляются. Плеер шлёт позицию раз в 15 с, на паузе, при выходе, в
конце серии. Первая минута чужой серии не записывается; осталось < 2 мин или
≥ 97 % — серия досмотрена, запись переходит на следующую (через сезон тоже).

Подробности API и режимов — `habits/media-agent/README.md`.

## 5. Форматы: что играет приставка

Приставка (Xiaomi Mi TV, Chrome в WebView) играет **только MP4**. MKV и AVI не
открывает, хотя кодеки внутри часто годные.

| В исходнике | Что делать | Как (ffmpeg) |
|---|---|---|
| видео **h264 / hevc** (также av1, vp9) | **копировать** | `-c:v copy` |
| видео mpeg4 (старые AVI), прочее | перекодировать | `-c:v libx264 -preset veryfast -crf 21 -pix_fmt yuv420p` |
| звук **AAC / MP3 стерео** | копировать | `-c:a copy` |
| звук AC3, DTS, 5.1 | в AAC стерео | `-c:a aac -b:a 160k -ac 2` |
| субтитры, обложка-картинка, главы | выбросить | `-sn -dn -map_chapters -1`, и `-map 0:v:0` (обложка — тоже «видео») |
| контейнер | всегда MP4 | `-movflags +faststart` |

**Звуковая дорожка — одна.** `<video>` в Chromium/WebView не переключает
встроенные дорожки (`audioTracks` выключен, проверено на Chrome 136) — играет
первая. Поэтому отправляем с `--audio 0` (нужная — обычно первая, русская).
Выбор перевода — план в разделе 10.

**Замеры скорости:**

| Операция | Скорость |
|---|---|
| x264 veryfast, SD (720×400), на i7 | 17–29× реального времени |
| x264 на i3 мини-сервера | ~8× — поэтому кодируем на дев-машине |
| копия видео 1080p + звук в AAC | упирается в чтение диска: фильм 13,8 ГБ — 71 с с NVMe; с переносного USB-диска ~25 МБ/с |
| передача по вайфаю (`cat` в SSH) | 25–28 МБ/с |

## 6. Скрипты (`habits/media-agent/`)

### `send-series.py` — добавить сериал или фильм (основной)

Сам решает по каждому файлу (таблица из раздела 5), печатает план, работает
конвейером (сборка и отдача параллельно), пропускает уже отправленное, при
пропаже сети ждёт её до 30 минут. Оригиналы не трогает.

```bash
S=habits/media-agent/send-series.py
python3 $S "/путь/Сериал (год)" --audio 0 --dry-run    # 1. план
nohup python3 -u $S "/путь/Сериал (год)" --audio 0 \
  --workdir /media/resager/4tbWdPortable/rudb/temp > /media/resager/4tbWdPortable/rudb/temp/имя.log 2>&1 &
python3 $S "/путь/Film.2020.1080p.mkv" --audio 0 --name "Фильм (2020)"   # фильм
python3 $S "/путь/Сериал" --only "Season 02"            # часть
python3 $S "/путь/Коллекция фильмов" --films --audio 0  # папка ФИЛЬМОВ
```
- Сериал → `/mnt/media/rudb/media/serials/<имя папки>` (структура сезонов
  сохраняется), фильм → `/home/res/rudb/media/films`.
- **`--audio`**: «0», «0,11» (несколько дорожек) или «all». Приставка играет
  первую из взятых.
- **`--scale` / `--crf` / `--bitrate` / `--preset`**: «720p», «1280x720», «70%»,
  качество 18…28, битрейт «6M»/«2500k» (один проход, `-maxrate` 1,5×,
  `-bufsize` 3×) и пресет x264. Включают перекодирование видео. Оценка времени считает раскодирование исходника и
  сжатие результата отдельно (x264 veryfast на i7-11370H: 1080p→1080p вчетверо
  быстрее реального времени, 1080p→720p лишь немногим быстрее, 720×304 — в
  тридцать раз); размер на выходе — около 3,5 Мбит/с на 1080p при crf 21.
- **`--films`**: папка — не сериал, а набор фильмов; каждый файл уезжает в
  библиотеку фильмов отдельной плиткой, имя собирает `film_name()` (номер в
  начале, год из середины в скобки, хвост раздачи срезан). Без ключа папка
  всегда считается сериалом.
- **Имя папки = название в медиатеке и запрос для постера**: «Legion (2017)»,
  а не «Legion.S01-03.1080p.LostFilm».
- `--workdir`: место на ~2 собранных файла. На `4tbWdPortable` его много; том
  `a25e7fed…` (значение по умолчанию) почти заполнен.

### `convert-watch.py` — сторож папки «положил и забыл» (v2.113)

Юзерский таймер на дев-машине (`habits-convert-watch.timer`, раз в 10 минут)
смотрит `…/rudb/temp/convert_and_del/{films,serials}`, зовёт `send-series.py`
и после проверки убирает исходник. Устройство и грабли:

- **Берёт только устоявшееся**: отпечаток (число файлов, суммарный размер,
  максимальный mtime) должен совпасть с прошлым прогоном и пролежать
  `--settle` секунд (600). Без этого подхватывался бы качающийся торрент.
- **Два прогона разом не идут**: `flock` на `~/.local/state/habits-convert/lock`
  — он общий на машину, а не на папку: ffmpeg всё равно один.
- **Место проверяется с двух сторон**: `df` на приставке по той библиотеке,
  куда поедет (фильмы на системном диске, сериалы на внешнем — разные диски,
  и у фильмов места мало), и `statvfs` на workdir под временный MP4 (самый
  большой файл × 1,5 — спул держит один файл за раз).
- **Исходник удаляется только после проверки**, что каждый файл лёг на ту
  сторону с ненулевым размером; три неудачи подряд — элемент откладывается.
  Пути назначения считаются теми же правилами, что у `send-series.py`
  (`destinations()`), и это место легко рассинхронизировать — при правке
  правил имён в `send-series.py` поправить и здесь.
- **Одиночный файл едет с `--name film_name(...)`**: без ключа
  `send-series.py` взял бы имя файла как есть, и плитка называлась бы
  «Fantastic.Beasts.2022.Lic.BDRip.MegaPeer».
- Журнал — файл на прогон в `~/.local/state/habits-convert/log` и то же
  в `journalctl --user -u habits-convert-watch`.

### `send-photos.py` — альбом фотографий из ZIP

```bash
python3 habits/media-agent/send-photos.py "/путь/Альбом.zip" --dry-run
python3 habits/media-agent/send-photos.py "/путь/Альбом.zip" [--name "Имя"] [--merge]
```
Архив уходит одним файлом в `/home/res/rudb/media/foto`, распаковывается там в
скрытую папку и переезжает на место одним `mv`. Папка внутри архива = альбом;
снимки в корне архива — альбом по имени архива. В конце скрипт открывает
альбом у агента, и тот в фоне собирает копии (~1,1 с на снимок 24 Мп на i3).
Свадьба Вероники и Андрея (75 снимков, 425 МБ): передача 16 с, распаковка 4 с.

### `recode-remote.py` — перекодировать то, что уже лежит на мини-сервере

Три стадии в потоках: скачать → собрать здесь → вернуть; **удаляет исходник**
после проверенного переименования. Своё SSH-соединение у каждой сетевой стадии,
keepalive, ожидание сети до 30 минут. Папки берёт из конфига агента.
```bash
python3 habits/media-agent/recode-remote.py --only "Название" --dry-run
python3 habits/media-agent/recode-remote.py --root /путь/на/сервере --workdir …
```
Запуск по расписанию — через `systemd-run --user --on-calendar="YYYY-MM-DD HH:MM:00" …`
(так гоняли The Big Bang Theory ночью: 202 серии за 2 ч 27 мин, три обрыва сети
пережиты без ошибок). Ноутбук при этом на зарядке и с открытой крышкой: на
зарядке он по бездействию не засыпает, крышка — усыпит.

### Прочие
- `send-film.py` — старый вариант для одного фильма (перекрыт `send-series.py`).
- `tvconvert.py` — подготовка библиотеки на месте (перепаковка, имена под Plex).

## 7. Страница плеера на приставке — что важно знать

- После «Начать» — режимы **Визуальный** (по умолчанию) / **Файлы**. В
  приложении «Начать» нажимается само.
- Визуальный: разделы «Продолжить просмотр», «Очередь», «Сериалы», «Фильмы»,
  «Музыка»; плеер открывается только по выбору плитки; стрелки ходят по сетке
  по координатам (`spatialMove`).
- Сериал играет сезон за сезоном (`/api/next-season`; папки прямо в корне
  библиотеки сезонами не считаются, иначе фильм «А/» продолжился бы фильмом «Б/»).
- Очередь с главной хранится в `localStorage` приставки; позиции — на агенте.

## 8. Приложение «Habits TV» для Android TV (`habits/tv-app`)

WebView на весь экран, Java без библиотек, APK ~21 КБ, Android 5+.
Зачем: встроенный браузер приставки водит курсором, приложение даёт настоящие
стрелки.

```bash
cd habits/tv-app
./build.sh            # dist/habits-tv.apk
./build.sh --deploy   # + выложить: http://192.168.0.79/tv/app/habits-tv.apk (значок Android в шапке страницы в браузере)
```

- Нужны JDK 17 и `~/Android/Sdk` (есть; Gradle 8.13 и AGP 8.13.2 в кэше).
- **Ключ подписи** создаётся при первой сборке в `~/.config/habits-tv/`, вне
  репозитория. Потерять — значит ставить обновление только после удаления старой версии.
- **targetSdk 34, не 36**: при 36 кнопку «Назад» забирает системный жест
  (predictive back), и она закрывала приложение вместо шага назад.
- Долгое «Назад» — экран адреса (`KeyEvent.isLongPress`, запасной порог 800 мс).
- Перед новой версией поднимать `versionCode` в `app/build.gradle`.

**Как проверять без приставки** (так и проверяли): в SDK нет образа Android TV,
но телефонный образ `system-images/android-36.1/google_apis_playstore/x86_64`
годится. Создать AVD с `hw.lcd.width=1920`, `hw.lcd.height=1080`,
`hw.lcd.density=320` (страница выходит шириной 960 CSS-пикселей, как на
приставке), `hw.dPad=yes`, `hw.keyboard=yes`, запустить
`emulator -avd … -no-window -no-audio -gpu swiftshader_indirect`, дальше
`adb install -r dist/habits-tv.apk`, `adb shell input keyevent KEYCODE_DPAD_DOWN|…_CENTER|…_BACK`,
`adb shell input keyevent --longpress KEYCODE_BACK`, снимки `adb exec-out screencap -p`.
После теста удалить AVD — он занимает гигабайты на `/home`.

Установка на приставку: скачать APK по ссылке и разрешить установку из
источника, либо на приставке включить «Отладку по сети» и `adb connect <ip>:5555`.
