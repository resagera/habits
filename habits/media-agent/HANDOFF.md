## 1. Что это и как устроено

```
дев-машина resager-tuf (i7-11370H)          мини-сервер res-i3 (i3-6100U)            ТВ-приставка Xiaomi
─────────────────────────────────           ─────────────────────────────            ────────────────────
исходники фильмов/сериалов           ──SSH──▶  /mnt/media, /home/res/…               браузер или приложение
ffmpeg: собираем MP4 здесь (быстрее)            habits-media-agent :8410  ◀──HTTP──  «Habits TV»
скрипты habits/media-agent/*.py                 nginx :80  /tv/ → :8410                http://192.168.0.79/tv/
сборка агента (Go) и APK                        habits-agent (мониторинг)
                                                        │
                                                        └──WSS──▶ прод telegram.resager.ru (только шина команд
                                                                   пульта с телефона; видео через прод не идёт)
```

- **Медиаагент** (`habits/media-agent`, Go) раздаёт страницу плеера, каталог,
  файлы с Range, постеры, позиции просмотра, APK приложения. Слушает только
  `127.0.0.1:8410`, наружу — через nginx.
- **Страница плеера** открывается на приставке: в браузере (там курсор) или в
  приложении «Habits TV» (там стрелки пульта). Телефон может управлять ею через
  страницу «Пульт ТВ» в Telegram-приложении Habits: приставка показывает код, пульт
  подключается через прод. Эту часть (пульт, прод) для работы с медиасервером
  трогать не нужно.
- **Кодирование** делается на дев-машине: на i3 x264 идёт ~8× реального
  времени, на i7 — 15–24×.

## 2. Доступы и подключение

| Что | Где |
|---|---|
| адрес мини-сервера | по имени **`res-i3.local`** (DHCP уже переносил его `.79 → .80`, 17.10.2026; в `habits-recode.conf` поэтому имя, а не IP) |
| пользователь | `res` |
| пароль SSH (и sudo — тот же) | `~/.config/habits-recode.conf` на дев-машине (host/user/password, права 0600) |
| ключ подписи APK | `~/.config/habits-tv/release.jks` + `keystore.properties` на дев-машине — **не терять** (см. 8) |

**Как подключаться — только через paramiko** (python3 на дев-машине):

- `sshpass` нет; обычный `ssh` отказывается спрашивать пароль — у хоста сменился
  ключ (в `~/.ssh/known_hosts` старая ECDSA-запись, сервер теперь ED25519;
  known_hosts пользователя не трогали);
- в `paramiko.connect` обязательно `allow_agent=False, look_for_keys=False`, иначе
  аутентификация по паролю падает с «No existing session»;
- sudo: `sudo -S -p "" bash -c '<команда>'` и пароль в stdin;
- команды для удалённой оболочки экранировать `shlex.quote` (не `repr`);
- готовый класс с переподключением: `Remote` в `habits/media-agent/recode-remote.py`:
  ```python
  import importlib.util
  spec = importlib.util.spec_from_file_location('rr', 'habits/media-agent/recode-remote.py')
  rr = importlib.util.module_from_spec(spec); spec.loader.exec_module(rr)
  r = rr.Remote(*rr.load_access())          # доступ из ~/.config/habits-recode.conf
  rc, out, err = r.run('df -h /mnt/media')  # run / pull / push / size / duration / wait_online
  r.close()
  ```
  Передача файлов — через `cat` в канале SSH (`push`/`pull`): SFTP в один поток
  вдвое медленнее (13 против 25–28 МБ/с).

## 4. Медиаагент

**Конфиг** `~/.config/habits-media-agent.conf` (сейчас):
```ini
roots = /mnt/media/rudb/media/serials/ | Сериалы | video
roots = /mnt/mybook/rudb/media/serials/ | Сериалы (новый диск) | video
roots = /home/res/rudb/media/music/playlist | Музыка Вероники | music
roots = /home/res/rudb/media/films | Фильмы | video
roots = /home/res/rudb/media/video | Видеоролики | clips  # постеры не ищутся
roots = /home/res/rudb/media/foto | Фото | photo
roots = /mnt/mybook/rudb/media/anime/ | Аниме | anime
addr = 127.0.0.1:8410
base = /tv
```
Формат: `путь | Название | вид (video, anime, clips, music, photo)`. Вид
`anime` — тот же `video` (`isVideoLib`: постеры, «Инфо», поиск в интернете,
разбор по качеству), но плитки уезжают в свой раздел «Аниме» после «Фильмов». Вид `photo` —
раздел «Фото и видео»: в альбомах живут и снимки, и ролики. Ещё
`admin_pin = …` — PIN админки на странице (без него админка выключена),
необязательный `ytdlp` (путь к yt-dlp; не задан — ищется в `~/bin` и `PATH`),
`trash_days` (3), `backup_dir` (куда класть копии разметки —
обязательно на ДРУГОЙ диск, иначе копия умрёт вместе с оригиналом; на res-i3
`/mnt/media/rudb/backups/habits-media`), `backup_days` (7) и `low_space_gb`
(10, 0 — не следить). Недоступная папка
(диск не примонтирован) не выбрасывается, а подхватывается, когда появится.

**Кэш** `~/.cache/habits-media/`: `probe.json` (разбор ffprobe), `progress.json`
(«Продолжить просмотр»), `posters/*.miss` (промахи поиска постеров, сутки),
`app/habits-tv.apk`, `photos/` (превью и экранные копии снимков, ~0,3 МБ на
снимок), `room` (постоянное имя комнаты для пульта), `secret` (ключ
подписи ссылок на файлы), `transcoded/` (копии, перекодированные кнопкой на ТВ),
`collections.json` + `collections/<id>.jpg` (папки-подборки и их обложки).

**id файлов и папок — хеш пути** (`sha256(path)[:9]`). Сменили путь — сменились
все id. `progress.json` переживает это: запись хранит `dir` + `rel` без
расширения и находит файл заново (так пережили и `.avi → .mp4`, и переезд диска
— при переезде `dir` переписали скриптом).

**Сборка и выкладка агента** (с дев-машины):
```bash
cd habits/media-agent
GOTOOLCHAIN=auto /usr/local/go/bin/go test ./...
GOOS=linux GOARCH=amd64 GOTOOLCHAIN=auto /usr/local/go/bin/go build -o /tmp/habits-media-agent .
# залить в ~/bin/habits-media-agent.new, chmod +x, mv поверх, systemctl --user restart habits-media-agent
```
Страница плеера `player.html` вшита в бинарник (`go:embed`): правка страницы =
пересборка и выкладка агента.

**Раскладка медиатеки** (визуальный режим, `catalog.go`) — по структуре папок,
не по названиям: сериал — папка с папками-сезонами; фильм — видеофайл или папка
ровно с одним видео; несколько видео без сезонов — мини-сериал; музыка — каждая
папка, где прямо лежат треки; видеоролики — ролик из корня или папка с роликами;
фото — папки первого уровня со снимками (`photos.go`). Пустые «Видеоролики» и
«Фото» не показываются.

**Папки-подборки** (`collections.go`, v2.112) — «Гарри Поттер»,
«Фантастические твари»: карточка в том же разделе, что её содержимое, внутри —
фильмы по порядку. **Виртуальные**: на диске ничего не двигается, запись —
список путей и порядок в `collections.json`. Так фильм может быть и в папке, и
в общем списке (галочка «только в папке» убирает его из общего), а
«Продолжить просмотр», отметки заставки и кадры, привязанные к пути, не
ломаются. Переименование в админке состав переживает (`collStore.move`).
Описание папки — только ручное: в интернете «коллекции» нет.

**Музыка по ссылке** (`ytdlp.go`, v2.120, очередь — v2.121) — «📥» у папки →
«⬇ По ссылке»: `yt-dlp -x --audio-quality 0` фоновой задачей, звук приезжает в
выбранную папку (в том числе вложенную). Имя файла — `%(title).150B
[%(id)s].%(ext)s`: вся музыка в медиатеке собрана тем же yt-dlp, и новое не
должно выделяться. Качает во временную папку кэша и переносит оттуда только
готовый звук, поэтому обрыв не оставляет мусора в библиотеке; папки, оставшиеся
от убитой перезапуском закачки, сносятся на старте агента.

Ссылок можно дать сразу несколько, по одной в строке: они встают в очередь
(`fetch-queue.json` в кэше) и качаются по одной, одной задачей на всю очередь.
Очередь **на диске**, а не в памяти задачи: деплой перезапускает агента, и
`fetchWorker` поднимает её сам (раз в 30 с; он же берётся за дело, если ссылки
положили во время другой задачи). «✖ Остановить» снимает всю очередь — иначе
`fetchWorker` поднял бы её заново через полминуты. Видна и снимается на вкладке
«Задачи».

**Сам `yt-dlp` в репозитории не лежит и обновляется отдельно** — он ломается
вслед за YouTube; состояние и кнопка «⬆ Обновить yt-dlp» на «Обслуживании».
Проверено вживую 19.10.2026: 10 минут звука (opus 127 кбит/с, 10 МБ) за 25 с;
очередь из трёх ссылок (одна битая) — две доехали, битая ушла строкой в отчёт;
ссылка, положенная во время закачки, дождалась своей очереди, а снятая не
скачалась; после перезапуска агента на середине работы очередь поднялась сама
через 24 с.

**Постеры** ищутся при первом показе плитки: IMDb (латиница; различает фильм и
сериал по типу и году — «The Gentlemen» 2019 против сериала 2024) и Википедия
(кириллица, `pilicense=any`). Кладутся **рядом** с фильмом/папкой сериала под
тем же именем (`Fauda.jpg`). Свою картинку можно подложить руками — она главнее.
Название для поиска чистится от релизных тегов (`cleanTitle`, покрыт тестом).

**«Продолжить просмотр»** (`progress.go`): запись на сериал/фильм, до 20, старше
полугода удаляются. Плеер шлёт позицию раз в 15 с, на паузе, при выходе, в
конце серии. Первая минута чужой серии не записывается; осталось < 2 мин или
≥ 97 % — серия досмотрена, запись переходит на следующую (через сезон тоже).

Подробности API и режимов — `habits/media-agent/README.md`.

## 5. Форматы: что играет приставка

Приставка (Xiaomi Mi TV, Chrome в WebView) играет **только MP4**. MKV и AVI не
открывает, хотя кодеки внутри часто годные.

| В исходнике | Что делать | Как (ffmpeg) |
|---|---|---|
| видео **h264 / hevc** (также av1, vp9) | **копировать** | `-c:v copy` (+ `-tag:v hvc1` для hevc) |
| видео mpeg4 (старые AVI), прочее | перекодировать | `-c:v libx264 -preset veryfast -crf 21 -pix_fmt yuv420p` |
| звук **AAC / MP3 стерео** | копировать | `-c:a copy` |
| звук AC3, DTS, 5.1 | в AAC стерео | `-c:a aac -b:a 160k -ac 2` |
| субтитры, обложка-картинка, главы | выбросить | `-sn -dn -map_chapters -1`, и `-map 0:v:0` (обложка — тоже «видео») |
| контейнер | всегда MP4 | `-movflags +faststart` |

**HEVC играет приставка, но не браузер компьютера.** Chrome и Firefox на
Linux HEVC не собирают: `canPlayType` пуст для любой подписи (`hvc1`, `hev1`,
8 и 10 бит; проверено на Chrome 136). Файл открывается без ошибки, звук и
длительность есть, `videoWidth` — ноль: на вид «сломанное видео». Поэтому
страница спрашивает кодеки у своего браузера (`screenCodecs`/`codecHere`) и
уточняет вердикт агента — тот про приставку; непроигрываемое помечается
«⚠ hevc не играет в этом браузере», нажатие ставит задачу с профилем `video`
(h264), готовую копию играют оба экрана. Отправка hevc по-прежнему копирует
(время и качество), но говорит это в плане; `--h264` перекодирует сразу.
В MP4 hevc подписывается `hvc1`, а не `hev1` по умолчанию ffmpeg: hev1 не
берут и те браузеры, которые HEVC умеют (Safari, Chrome на Windows и Mac).

**Играет первая дорожка, но везём все.** `<video>` в Chromium/WebView не
переключает встроенные дорожки (`audioTracks` выключен, проверено на Chrome
136) — играет первая. Выбрасывать остальные при отправке всё равно не стоит:
места они берут мало, а вернуть выброшенную можно только переотправкой целой
серии. Поэтому `--audio` по умолчанию `all` и у `send-series.py`, и у сторожа
папки; порядком дорожек в исходнике и задаётся озвучка по умолчанию.
⚠ Названия дорожек в MP4 не переезжают (контейнер их так не хранит) — остаются
только метки языка, так что различать их можно лишь по порядку. Порядок у рипа
может гулять: у Murderbot S01 первой лежит HDrezka, а в E04 — TVShows, и
озвучка меняется посреди сезона. Выбор перевода — план в разделе 10.

**Замеры скорости:**

| Операция | Скорость |
|---|---|
| x264 veryfast, SD (720×400), на i7 | 17–29× реального времени |
| x264 на i3 мини-сервера | ~8× — поэтому кодируем на дев-машине |
| копия видео 1080p + звук в AAC | упирается в чтение диска: фильм 13,8 ГБ — 71 с с NVMe; с переносного USB-диска ~25 МБ/с |
| передача по вайфаю (`cat` в SSH) | 25–28 МБ/с |

## 6. Скрипты (`habits/media-agent/`)

### `send-series.py` — добавить сериал или фильм (основной)

Сам решает по каждому файлу (таблица из раздела 5), печатает план, работает
конвейером (сборка и отдача параллельно), пропускает уже отправленное, при
пропаже сети ждёт её до 30 минут. Оригиналы не трогает.

```bash
S=habits/media-agent/send-series.py
python3 $S "/путь/Сериал (год)" --dry-run    # 1. план
nohup python3 -u $S "/путь/Сериал (год)" > ~/имя.log 2>&1 &   # 2. отправка
python3 $S "/путь/Film.2020.1080p.mkv" --name "Фильм (2020)"   # фильм
python3 $S "/путь/Сериал" --only "Season 02"            # часть
python3 $S "/путь/Коллекция фильмов" --films  # папка ФИЛЬМОВ
```
- Сериал → `/mnt/mybook/rudb/media/serials/<имя папки>` (новый диск, структура
  сезонов сохраняется), фильм → `/home/res/rudb/media/films`. Сериал с таким
  именем, уже лежащий на старом диске (`/mnt/media/…/serials`), доезжает туда
  же: `series_dest()` спрашивает у той стороны `test -d`.
- **`--audio`**: «0», «0,11» (несколько дорожек) или «all». Приставка играет
  первую из взятых.
- **`--scale` / `--crf` / `--bitrate` / `--preset`**: «720p», «1280x720», «70%»,
  качество 18…28, битрейт «6M»/«2500k» (один проход, `-maxrate` 1,5×,
  `-bufsize` 3×) и пресет x264. Включают перекодирование видео. Оценка времени считает раскодирование исходника и
  сжатие результата отдельно (x264 veryfast на i7-11370H: 1080p→1080p вчетверо
  быстрее реального времени, 1080p→720p лишь немногим быстрее, 720×304 — в
  тридцать раз); размер на выходе — около 3,5 Мбит/с на 1080p при crf 21.
- **`--h264` / `--tune` / `--replace`**: перекодировать в h264 даже
  копируемое (нужно для hevc — его не играет браузер компьютера),
  `-tune animation` для рисованного и перезапись того, что уже лежит на той
  стороне (по умолчанию такие файлы пропускаются, и переделанный файл не уехал
  бы). Пути при перезаписи те же, поэтому позиции просмотра, отметки, доп
  материалы и постер остаются на месте.
- **`--films`**: папка — не сериал, а набор фильмов; каждый файл уезжает в
  библиотеку фильмов отдельной плиткой, имя собирает `film_name()` (номер в
  начале, год из середины в скобки, хвост раздачи срезан). Без ключа папка
  всегда считается сериалом.
- **Имя папки = название в медиатеке и запрос для постера**: «Legion (2017)»,
  а не «Legion.S01-03.1080p.LostFilm».
- **Сезон = папка, и только папка.** Структуру исходника скрипт переносит один
  в один (`dst = корень + rel`), а агент имя файла не разбирает вовсе
  (`hasSeasonDirs` в `catalog.go` просто смотрит, есть ли видео в подпапках).
  Значит, серии, попавшие не в свою папку, в медиатеке теряются: отдельного
  сезона нет, а сами они оказываются внутри чужого, да ещё в начале списка —
  натуральная сортировка ставит `S01E01` перед `s03e01`. Так уехал первый сезон
  Misfits (21.10.2026 разобрано: шесть серий S01 лежали в «Season 03»).
  Поэтому в плане теперь есть проверка `season_mismatches()`: номер из имени
  файла (`S01E02`, `1x02`) сверяется с номером из имени папки («Season 02»,
  «Season-1», «Сезон 2», диапазон «Season 1-3»), и при расхождении скрипт
  печатает, что куда едет, и выходит с кодом 2 — перебить можно `--as-is`.
  Папка без номера («Specials», «2009», корень сериала) не проверяется: там
  нечего сверять. Сторож `convert-watch.py` на коде 2 оставляет исходник и
  пишет причину в журнал, так что битая раскладка не попадёт в библиотеку
  молча, да ещё с удалением исходника.
- `--workdir` руками не нужен: скрипт сам берёт первую папку из `WORKDIRS`, в
  которую можно писать и где есть `WORKDIR_FREE` (8 ГБ — на две 1080p-серии
  разом); порядок — сначала внутренние NVMe, потом внешние USB, чтобы чтение
  исходника не спорило с записью за одну шину. Если запаса нет нигде — берётся
  самая свободная с отметкой в логе, если недоступны все — внятная ошибка.
  Раньше по умолчанию стоял один том `a25e7fed…` (съёмный, то смонтирован, то
  нет), и запуск без `--workdir` падал `PermissionError` уже ПОСЛЕ показа плана.

### `convert-watch.py` — сторож папки «положил и забыл» (v2.113)

Юзерский таймер на дев-машине (`habits-convert-watch.timer`, раз в 10 минут)
смотрит папки `convert_and_del/{films,serials,anime}`, зовёт `send-series.py`
и после проверки убирает исходник. Устройство и грабли:

- **Папок-сторожей несколько** (`WATCHES`, с 26.10.2026): `…/2tb-ext-part/rudb/temp/`
  и `…/a25e7fed-…/home/sah/rudb/`. Ключ в `state.json` — `<папка>|<sub>/<имя>`,
  иначе одноимённые элементы из разных папок делили бы одно состояние; в журнал
  идёт короткая метка по точке монтирования (`[2tb-ext-part] films/…`), и только
  когда папок больше одной. Чистка памяти (`forget()`) трогает ТОЛЬКО папки,
  живые в этом прогоне: отвалившийся диск иначе обнулил бы счётчик неудач, и
  сторож снова взялся бы за трижды упавшее. Ключи старого формата (без `|`)
  выбрасываются — один раз сбрасывается устаканивание, и всё.
- ⚠ **Одинаковое имя в двух папках = один путь на приставке.** `clashes()`
  берёт только первое. Без этого второе ушло бы в `send-series.py`, тот счёл бы
  его «уже на месте» и ничего не отправил, `verify()` нашёл бы файл по имени и
  признал доставку — и сторож удалил бы исходник, не отправив его.

- **Берёт только устоявшееся**: отпечаток (число файлов, суммарный размер,
  максимальный mtime) должен совпасть с прошлым прогоном и пролежать
  `--settle` секунд (600). Без этого подхватывался бы качающийся торрент.
- **Два прогона разом не идут**: `flock` на `~/.local/state/habits-convert/lock`
  — он общий на машину, а не на папку: ffmpeg всё равно один.
- **Место проверяется с двух сторон**: `df` на приставке по той библиотеке,
  куда поедет (фильмы на системном диске, сериалы на новом внешнем, а если
  сериал уже есть на старом — на старом: диски разные, и у фильмов места мало),
  и `statvfs` на workdir под временный MP4 (самый большой файл × 1,5 — спул
  держит один файл за раз).
- ⚠ **Workdir выбирается сам** (`pick_workdir()`, с 26.10.2026) — первый из
  `ss.WORKDIRS`, куда можно писать и где влезает `biggest × 1,5`. До этого в
  файле стояла константа рядом с самой папкой-сторожем, и она же передавалась
  в `send-series.py` ключом `--workdir`, перебивая его собственный выбор. Диск
  с папкой забивается первым — сторож исправно запускался каждые 10 минут и
  каждый раз писал «мало места в …: свободно 3.7 ГБ, нужно 13.1 ГБ —
  пропускаю». Снаружи это выглядело как «агент не запустился». В журнале теперь
  строчка «собираю в <папка>: свободно N».
- **Исходник удаляется только после проверки**, что каждый файл лёг на ту
  сторону с ненулевым размером; три неудачи подряд — элемент откладывается.
  Пути назначения считаются теми же правилами, что у `send-series.py`
  (`destinations()`), и это место легко рассинхронизировать — при правке
  правил имён в `send-series.py` поправить и здесь.
- **Три подпапки — три раздела медиатеки**: `films` (фильм, набор `--films`
  или папка с одним видео), `serials` (сериал) и `anime` (`--anime`,
  с v2.122.1). Раскладка внутри и проверка доставки — те же правила, что у
  `send-series.py`; у аниме и место проверяется по корню библиотеки аниме.
- **По умолчанию `--audio all` и `--h264`** (с 26.10.2026). Дорожки все: играть
  приставка будет первую, но выброшенную не вернуть иначе как переотправкой.
  Видео приводится к h264, потому что hevc играет приставка, а браузер
  компьютера нет (раздел 5) — а сторож работает сам, и некому заметить чёрный
  экран. Это дорого: hevc-фильм на 9 ГБ вместо копирования идёт через x264
  (десятки минут против двух). `--no-h264` возвращает копирование.
  Смысл `--h264` в `send-series.py` при этом пришлось уточнить: было «не
  копировать видео никогда», стало «привести к h264» — иначе сторож гонял бы
  через x264 и то, что уже h264.
- **Одиночный файл едет с `--name film_name(...)`**: без ключа
  `send-series.py` взял бы имя файла как есть, и плитка называлась бы
  «Fantastic.Beasts.2022.Lic.BDRip.MegaPeer».
- Журнал — файл на прогон в `~/.local/state/habits-convert/log` и то же
  в `journalctl --user -u habits-convert-watch`.

### My Book: сон и парковка головок (26.10.2026)

Внутри коробки `WDC_WD80EDAZ-11CEWB0` (Ultrastar He10), мост USB 1058:25ee.
**Это две независимые вещи, и путать их нельзя.**

- **Сон шпинделя — лечится штатно, root нужен один раз.** Ядро диск не
  укладывает (`manage_start_stop` = 0, runtime PM `on`, autosuspend -1); таймер
  в мосте и виден в странице Power Condition: `STANDBY_Z` = 1, `SZCT` = 18000
  (×100 мс = 30 минут), оба помечены `cha: y` — **изменяемые**. Значит ни WD
  Drive Utilities, ни Windows не нужны: `~/bin/mybook-nosleep.sh` делает
  `sdparm --clear=STANDBY_Z --set=SZCT=0 --save`. Если `--save` не пройдёт,
  скрипт применит без сохранения и скажет, что настройка сбросится с питанием.
- ⚠ **Парковка головок через мост недостижима.** `idle3ctl` ходит старым ioctl
  `HDIO_DRIVE_CMD` → `Invalid argument`; APM диск не поддерживает вовсе
  (`hdparm -B` → `not supported`); страницы `IDLE_A/B/C` у моста
  неизменяемые (`cha: n`). Единственный способ поменять таймер — вынуть диск из
  коробки и подключить по SATA. Поэтому головки держатся загруженными снаружи:
  служба `mybook-keepalive.service` читает с платтера раз в 60 с.
- **Интервал выбран по SMART, а не на глаз**: `Load_Cycle_Count` 1705 при
  `Power_On_Hours` 70 → снятие примерно раз в 2,5 минуты простоя, интервал
  60 с даёт двукратный запас. Проверка правильности — рост
  `Load_Cycle_Count` между двумя прогонами `mybook-diag.sh`: встал — попали.
- **Служба с циклом, а не таймер systemd**: при интервале в минуту таймер дал
  бы 1440 запусков в сутки и столько же пар строк в журнале. Скрипт умеет оба
  режима: без второго аргумента — одно чтение и выход (удобно руками), с
  интервалом — цикл.
- ⚠ **Чтение должно быть `O_DIRECT` и каждый раз с нового места.** Без
  `O_DIRECT` его обслужит кэш страниц, и до диска запрос не дойдёт; с одного и
  того же места — кэш внутри диска (десятки МБ), и спящий диск не проснётся.
  Отсюда случайное смещение по файлу больше 2 ГБ. Путь кэшируется
  (`~/.cache/mybook-keepalive.target`), каталоги обходятся только когда файл
  пропал.
- ⚠ **Смещение считается из 4 байт `/dev/urandom` плюс `$RANDOM`.** Восемь байт
  (`od -tu8 -N8`) bash читает как ЗНАКОВОЕ число — смещение уходило в минус и
  `dd` падал с кодом 1 на каждом втором прогоне. Поймано тестом на дев-машине.
- **Сон пока ни разу не случался**: `Start_Stop_Count` 39 при
  `Power_Cycle_Count` 39 — шпиндель останавливался только вместе с питанием.
  Тридцатиминутный таймер есть, но за 70 часов не сработал (машину гасят
  раньше). Это не повод его не выключать, но и не аварийная ситуация.
- ⚠ **Root на res-i3 без пароля не даётся** (`sudo -n` → «a password is
  required»), поэтому `smartctl`, `sdparm`, `idle3ctl` и `hdparm` запускает
  пользователь. Для этого есть два готовых скрипта в `~/bin`:
  `mybook-diag.sh` (только читает, пишет в `/tmp/mybook-diag.txt` — оттуда
  файл забирается уже без root) и `mybook-nosleep.sh` (меняет таймер сна).
- Юниты, как и у остальных агентов, лежат только на машине
  (`~/.config/systemd/user/mybook-keepalive.service`), в репо — текстом в
  README. Сами скрипты в репо есть.

### Папки под кодом (29.10.2026)

`locks.go`. Закрытая папка не видна в медиатеке вовсе — ни плиткой, ни
строкой, ни по прямой ссылке. Проверяет агент: `s.visible(path, r)` стоит в
`/api/catalog` (через `openTiles`), `/api/browse` (`hideLocked`),
`/api/photos`, `/api/tracks`, `/api/playlists/{id}`, `/api/item`,
`/media/{id}`, `/photo/{id}`, `/poster/{id}`. Прятать в браузере было бы
бессмысленно: id — хеш пути, подпись `k` считается от него же.

Открывают кодом: `POST /api/unlock {pin}` ищет папку ПО коду (`locks.match`),
поэтому коды у папок разные и агент не даёт поставить одинаковые. Списка
закрытых папок наружу нет никогда. Билет — кука сеанса `htv_unlock`
(HttpOnly): её носит браузер, и не пришлось дописывать билет в каждый
`<img src>`. Срок — получас без обращений (`unlockIdle`) или `POST /api/lock`.
Подбор запирается после 5 промахов на 5 минут.

Хранение — `locks.json`, ключ **путь** папки, пин — sha256 с солью (кэш
уезжает в копию разметки в Telegram). Замок едет за папкой: `locks.move` в
`moveMemory`, `locks.forget` при удалении — иначе новая папка с тем же именем
открылась бы по старому коду.

Админка: вкладка «Папки под кодом» (выбор папки через общий `pickFolder`),
`GET/POST /api/admin/locks`, `POST /api/admin/locks/drop`. Коды наружу не
отдаются даже админке — только задать заново.

### Переезд папок между библиотеками — из админки (29.10.2026)

**Админка → Задачи → «📦 Переезд на другой диск».** Выбираешь «Откуда» и
«Куда» (библиотеки одного вида), дальше «Перенести всё» или по папке. Каждая
папка — своя задача с полосой по байтам, идут по одной, очередь на диске
(`migrate-queue.json`) переживает перезапуск агента. Код — `migrate.go`,
API: `GET/POST /api/admin/migrate`, `POST /api/admin/migrate/drop`.

Порядок: копия в `.habits-migrate` на диске-приёмнике (вне корней библиотек) →
сверка размеров → `rename` в библиотеку (тот же диск, значит мгновенно и
целиком) → перенос памяти агента → удаление исходника. До шага с `rename`
исходник не трогается вообще, а недокопированное догоняется следующим
прогоном: файлы того же размера второй раз не едут.

**Главное, что тут легко забыть:** id объекта в агенте — это `shortID` =
хеш ПУТИ. Переложить файлы и не переписать память значит осиротить всё, что
агент помнит. Поэтому есть `moveMemory(old, neu, isDir)` в `admin.go` — один
список для переименования и для переезда: `remember`, `moveProgress`,
`moveMarks`, `moveFrames`, `movePosters`, `statsStore.move`, `colls/favs/
links/extras.move` и `agentStore.move` (кэш `ffprobe`: пути, id и ключи с
временем правки). **Добавил новое хранилище, где ключ — путь или id, — впиши
его в `moveMemory`, иначе оно тихо осиротеет при первом же переименовании.**

Конфиг переезд не трогает: когда старая библиотека опустеет, строку `roots`
убрать руками.

### `move-library.py` — переезд библиотеки на другой диск (20.10.2026)

Единственный скрипт отсюда, который запускается **на res-i3**, а не с
дев-машины: копирование идёт по месту.

```bash
~/bin/move-library.py --from /home/res/rudb/media/films \
                      --to /mnt/mybook/rudb/media/films [--dry-run] [--notify] [--keep-source]
```
- **Зачем, если есть `mv`.** `shortID = sha256(путь)[:9]` — id файла в агенте,
  и по нему разложено всё, что агент помнит: `progress.json` (ключ, `file`,
  `season_id`, `dir`), `marks.json`, `favorites.json` и `links.json` (там
  вообще пути), `collections.json` (пути участников подборок), `stats.json`
  (id файлов по дням), `probe.json` (`probes` и `paths` — id → путь),
  `posters/<id>.jpg|.miss`, `frames/<id>/`, `photos/<id>-thumb.jpg`. Скрипт
  переписывает строки во всех json-ах кэша (копия `<файл>.before-move` рядом,
  **не** `.bak` — у агента свой `progress.json.bak`) и переименовывает файлы и
  папки, чьё имя начинается со старого id.
- **Ключ `probe.json`** — `версия|путь|размер|время правки`; после переезда
  время правки подновляется по факту, иначе на exFAT (округление до двух
  секунд) агент перечитал бы ffprobe-ом всю библиотеку.
- **Порядок:** проверки (место, корень есть в конфиге, на приёмнике пишется) →
  `rsync` при работающем агенте → стоп агента → повторный `rsync` → сверка
  каждого файла по размеру → память → корень в конфиге → старт агента →
  проверка через API (библиотека на месте, плиток не меньше) → и только теперь
  удаление исходника. Простой приставки — минута, а не всё копирование.
- **Если сорвалось** на шагах с памятью и дальше: конфиг и json-ы
  возвращаются из копий, агент поднимается на старом месте, исходник остаётся.
  Копия на приёмнике не убирается — следующий прогон её догонит. Прогон
  идемпотентен: источника нет, конфиг смотрит на новое место — «уже
  перевезено», код возврата 0.
- **Проверено** на выброшенной библиотеке из двух файлов — туда и обратно, с
  тёплым кэшем (`probe.json` переписался, ключи сошлись) и на exFAT.
- Чего он НЕ умеет: переносить часть библиотеки (корень в конфиге один) и
  чинить корзину, если в ней что-то лежит, — пути в `trash.json` он правит, но
  это стоит проверить глазами.

скрытую папку и переезжает на место одним `mv`. Папка внутри архива = альбом;
снимки в корне архива — альбом по имени архива. В конце скрипт открывает
альбом у агента, и тот в фоне собирает копии (~1,1 с на снимок 24 Мп на i3).
Свадьба Вероники и Андрея (75 снимков, 425 МБ): передача 16 с, распаковка 4 с.

### `recode-remote.py` — перекодировать то, что уже лежит на мини-сервере

Три стадии в потоках: скачать → собрать здесь → вернуть; **удаляет исходник**
после проверенного переименования. Своё SSH-соединение у каждой сетевой стадии,
keepalive, ожидание сети до 30 минут. Папки берёт из конфига агента.
```bash
python3 habits/media-agent/recode-remote.py --only "Название" --dry-run
python3 habits/media-agent/recode-remote.py --root /путь/на/сервере --workdir …
```
`--h264` поднимает вердикт до `video` и для hevc, который приставка играет как
есть (`--tune animation` — под рисованное): это путь «починить уже уехавшее»,
когда исходника на дев-машине не осталось. Файл уже в MP4 — `target_path()`
отдаёт тот же путь, и он перезаписывается через `.part` + `mv -f`, а `rm`
исходника не делается (`src == dst`).

Запуск по расписанию — через `systemd-run --user --on-calendar="YYYY-MM-DD HH:MM:00" …`
(так гоняли The Big Bang Theory ночью: 202 серии за 2 ч 27 мин, три обрыва сети
пережиты без ошибок). Ноутбук при этом на зарядке и с открытой крышкой: на
зарядке он по бездействию не засыпает, крышка — усыпит.

### Прочие
- `send-film.py` — старый вариант для одного фильма (перекрыт `send-series.py`).
- `tvconvert.py` — подготовка библиотеки на месте (перепаковка, имена под Plex).

## 7. Страница плеера на приставке — что важно знать

- После «Начать» — режимы **Визуальный** (по умолчанию) / **Файлы**. В
  приложении «Начать» нажимается само.
- Визуальный: разделы «Продолжить просмотр», «Очередь», «Сериалы», «Фильмы»,
  «Аниме», «Видеоролики», «Фото и видео», «Музыка»; плеер открывается только по
  выбору плитки; стрелки ходят по сетке по координатам (`spatialMove`).
- Любой раздел **сворачивается** стрелкой у названия (`secHTML`/`toggleSec`,
  `htv.secclosed` в `localStorage`): переключается прямо в DOM, без
  перерисовки, иначе пульт прыгал бы в начало списка.
- Сериал играет сезон за сезоном (`/api/next-season`; папки прямо в корне
  библиотеки сезонами не считаются, иначе фильм «А/» продолжился бы фильмом «Б/»).
- **Доп материалы** (`extras.go`, v2.122): папка `SPs`/`Specials`/`Extras`/
  «Доп материалы» внутри сезона или рядом с сезонами. Кнопка с ними видна
  всегда (`✚`), в счёт серий они не идут. Галочка «смотреть вместе со
  спешиалами» — на сеанс (`sessionStorage`, включена) и едет на агент
  параметром `extras=1` у `/api/browse` и `/api/next-season`; галочка «спешлы
  после каждой серии» — свойство сериала (`extras.json`, ключ — путь,
  `POST /api/extras`, выключена). Подмешивает агент, а не страница
  (`seasonItems`), иначе список на экране и то, что играется дальше само,
  разошлись бы. Порядок сезонов для автоперехода даёт `seasonChain`: допы либо
  после всех сезонов, либо не играются вовсе (при «после каждой серии» они уже
  внутри). Пара «серия → доп» — по порядку при равном числе, иначе по явному
  номеру (`S01E02`, `E12`); «первое число» не годится из-за `1080p` и `x265`.
- Очередь с главной хранится в `localStorage` приставки; позиции — на агенте.
- Фото: экран папки — снимок сверху, полоса превью и вложенных папок снизу;
  снимок меняется вслед за фокусом в полосе, OK — во весь экран (`#pfull`,
  стрелки листают по кругу, «Назад»/OK — обратно). Раздел «Фото» и
  «Видеоролики» на главной скрыты, пока пусты.
- Кнопка «Назад» приложения вызывает `window.habitsBack()`.
- v2.118: резервная копия разметки (`backup.go`, раз в неделю ZIP в
  `backup_dir` + отправка в Telegram через новую прод-ручку
  `POST /api/v1/tv/notify/file`, токен бота остаётся на проде) и присмотр за

  уезжает наружу. `backup_dir` по умолчанию — сам кэш, то есть тот же диск;

## 8. Приложение «Habits TV» для Android TV (`habits/tv-app`)

WebView на весь экран, Java без библиотек, APK ~21 КБ, Android 5+.
Зачем: встроенный браузер приставки водит курсором, приложение даёт настоящие
стрелки.

```bash
cd habits/tv-app
./build.sh            # dist/habits-tv.apk
./build.sh --deploy   # + выложить: http://192.168.0.79/tv/app/habits-tv.apk (значок Android в шапке страницы в браузере)
```

- Нужны JDK 17 и `~/Android/Sdk` (есть; Gradle 8.13 и AGP 8.13.2 в кэше).
- **Ключ подписи** создаётся при первой сборке в `~/.config/habits-tv/`, вне
  репозитория. Потерять — значит ставить обновление только после удаления старой версии.
- **targetSdk 34, не 36**: при 36 кнопку «Назад» забирает системный жест
  (predictive back), и она закрывала приложение вместо шага назад.
- Долгое «Назад» — экран адреса (`KeyEvent.isLongPress`, запасной порог 800 мс).
- Перед новой версией поднимать `versionCode` в `app/build.gradle`.

**Как проверять без приставки** (так и проверяли): в SDK нет образа Android TV,
но телефонный образ `system-images/android-36.1/google_apis_playstore/x86_64`
годится. Создать AVD с `hw.lcd.width=1920`, `hw.lcd.height=1080`,
`hw.lcd.density=320` (страница выходит шириной 960 CSS-пикселей, как на
приставке), `hw.dPad=yes`, `hw.keyboard=yes`, запустить
`emulator -avd … -no-window -no-audio -gpu swiftshader_indirect`, дальше
`adb install -r dist/habits-tv.apk`, `adb shell input keyevent KEYCODE_DPAD_DOWN|…_CENTER|…_BACK`,
`adb shell input keyevent --longpress KEYCODE_BACK`, снимки `adb exec-out screencap -p`.
После теста удалить AVD — он занимает гигабайты на `/home`.

Установка на приставку: скачать APK по ссылке и разрешить установку из
источника, либо на приставке включить «Отладку по сети» и `adb connect <ip>:5555`.
